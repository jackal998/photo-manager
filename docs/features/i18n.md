# Features — i18n

Entries for the **i18n** area of the feature inventory. The index and the section schema are in [`../features.md`](../features.md).

### Language switch
- **Area:** i18n

- **Entry point:** Three controls that all call `setLocale` in the i18n store ([frontend/src/i18n/useI18nStore.ts](../../frontend/src/i18n/useI18nStore.ts)): the toolbar toggle `main-lang-toggle` ([frontend/src/components/Toolbar.tsx](../../frontend/src/components/Toolbar.tsx)), labelled `EN` when English is active and `中` when 繁體中文 is; below 1100px of toolbar width, where that toggle folds away, the toolbar **⋯** menu's **Language** items `main-overflow-lang-en` / `main-overflow-lang-zh` ([#918](https://github.com/jackal998/photo-manager/issues/918)); and the menu bar's **View > Language** items `menu-view-lang-en` ("English") and `menu-view-lang-zh` ("中文 (繁體)") ([frontend/src/components/MenuBar.tsx](../../frontend/src/components/MenuBar.tsx)).
- **Trigger:** A click on the toggle (it cycles `en` ↔ `zh_TW`), or picking a locale under View > Language.
- **Behaviour:** `setLocale(code)` saves the choice as `R-LANG-1` states (`PATCH /api/settings`), then fetches `GET /api/i18n/{code}` and swaps in the new catalog; every label rendered through `useT()` / `t()` re-renders at once, with no page reload and no confirm dialog. If the persist fails, the failure is logged (`console.warn`) and the switch lasts for this session only; if the catalog fetch fails, the locale code still flips with an empty catalog, so the English fallbacks render. On page load `initI18n()` reads `ui.locale` from `GET /api/settings` and fetches that catalog, so the choice survives a reload and a relaunch. The manifest and result tree live in a separate Zustand store that a locale switch never touches. The retired desktop client rebuilt its whole window on a switch, which is why it needed a confirm prompt and the [#428](https://github.com/jackal998/photo-manager/issues/428) manifest-reload fix. The web needs neither, because React never destroys and recreates the component tree on a switch. The View > Language menu is a checkmark picker: the active locale's item carries a trailing `✓` (`aria-hidden`) and the other carries none, so both options stay visible. Picking the already-active locale still round-trips through `setLocale` (there is no no-op short-circuit).
- **Toolbar text in each locale:**
  - `main-scan-button`: `Scan` (en) / `掃描` (zh_TW)
  - `main-execute-button`: `Execute` (en) / `執行` (zh_TW)
  - `main-settings-button`: `Settings` (en) / `設定` (zh_TW)
  - `main-manifest-open-button`: `Open` (en) / `開啟` (zh_TW)
- **Conditions / variants:** The UI offers exactly the two shipped locales, `en` and `zh_TW`, hard-coded in all three controls. The backend discovers locales from the `translations/<code>.yml` files and lists them in the `available` field of `GET /api/i18n/{locale}` (an unknown code gets a 404), but the frontend does not read that list, so adding a third locale takes a new YAML file **and** a UI change. `GET /api/i18n/{locale}` serves only the `web.*` keys. The desktop-era namespaces that remain in `en.yml` are never sent to the browser.
- **Coverage gap closed (web audit fixes 5+6, [#669](https://github.com/jackal998/photo-manager/issues/669)):** a UI/UX sweep found the toggle worked but a whole class of components never called `useT()`, so switching to 中文(繁體) left them in English — notably both right-click context menus (main tree + Execute dialog), LockConfirmDialog, PruneConfirmDialog, RemoveFromListConfirmDialog, SettingsDialog, ExecuteDialog's own chrome, FullResViewer, PreviewPane (incl. its metadata labels), the `similarityLabel`/"Ref" formatter, FileRow's "Ref" badge, and two of DeleteConfirmDialog's three branches. All now route through `useT()`/`t('web.*', …)`; `tests/test_web_i18n_callsite_keys.py` pins every callsite key against `en.yml`, and both catalogs carry the identical `web.*` key set (verified — no asymmetry; **303 keys** as of the 2026-09-14 copy audit, **362** on 2026-09-29 and still symmetric).
- **Second coverage sweep (copy audit batch 1, 2026-09-14):** an owner trial found the same class of leak in surfaces the first sweep missed. Now catalog-driven: the whole **Scan dialog** including its running-state panel and source rows (the largest remaining English surface — see [Web — ScanDialog source/output persistence](web-ui.md#web--scandialog-sourceoutput-persistence)), the result tree's **group header row** ("Group 3 · 5 files" stayed English in a zh_TW session — `web.tree.*` is the first mirror of the desktop-era `tree.*` namespace), the Execute dialog's two **warning banners** and its preview `alt`, the near-duplicate similarity label (`~` → `~dup`), the **status-bar error lines** (which rendered raw backend developer text — see [Main window — status bar baseline](main-window.md#main-window--status-bar-baseline)), and the accessible names on the menu bar, the lock padlock and the inline decision control. Pluralisation was split per count in four places that read "1 groups" / "1 files" / "1 files found" / "row(s)". zh_TW punctuation was normalised to full-width in the Set-Action labels and the scan parity note. **Copy audit batch 2 (2026-09-18)** then settled both of the questions batch 1 had deferred. The three decision labels became the ONE site-wide vocabulary **Keep / Delete / Skip** (保留 / 刪除 / 略過) for the wire values `""` / `"delete"` / `"ignore"` — replacing four different triples (tree control `None / Delete / Ignore`, right-click `Keep (clear decision) / Delete / Remove from list`, Execute filter `All decided / Delete only / Remove only`, Execute badge `Delete / Remove`), with short forms on controls and long forms in menus and tooltips; every user-facing "delete" long form names the Recycle Bin and the Skip long form names the file's fate on disk first. The word "Remove"／「移除」 no longer renders as a decision label anywhere. **The two IMMEDIATE actions are worded apart from the staged one** (review round 2): the row control STAGES a reversible `user_decision='ignore'`, while the result-tree right-click item and the List menu FINALIZE `outcome='ignored'` under `R-SKIP-1` — so those two read **"Skip now — drop from this review"**／「立即略過 — 從本次檢閱中移除」 and **"Skip Selected now"**／「立即略過選取項目」 (`web.context_menu.skip_now`, `web.menu.list_remove`). One word for both would make the reversible and the irreversible action look identical. The **Action** column renders the classifier value through `web.classification.*` instead of the raw enum (`EXACT` → "Exact copy" / 「完全相同」) — and **layout slice C then removed that column outright** (open questions Q1): the classification never varies independently of the similarity badge beside it, so **Action** now heads the decision control and the classification moved to the badge's `title` tooltip, in the same `web.classification.*` words. See [Web — Daylight theme and results-tree framing](web-ui.md#web--daylight-theme-and-results-tree-framing) § Columns.
