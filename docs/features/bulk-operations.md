### Bulk regex — remove from list (deferred decision)
- **Area:** Bulk operations

- **Entry point:** The Set Action dialog's action combo (`action-action-combo`, [frontend/src/components/action/ActionDialog.tsx](../../frontend/src/components/action/ActionDialog.tsx)) — its **Skip** option (catalog key `web.decision.remove_from_list`, wire value `__ignore__`). The dialog opens from the toolbar's **Set Action…**, the menu bar's **Action → Set Action by Field…**, or a row's right-click **Set Action by Field…** — see [Web — Action dialog (Set Action by Field)](web-ui.md#web--action-dialog-set-action-by-field).
- **Trigger:** Build a match (field + pattern), pick **Skip** as the action, click **Apply**.
- **Behaviour:** Apply sends `POST /api/action/bulk-decide` with `action="__ignore__"`; the backend maps it to `user_decision='ignore'` on every matched row. Nothing is moved or deleted and no row leaves the tree yet: each matched row keeps `outcome=''` and shows **Skip** selected in its decision control. Unlike **Delete**, Skip applies with no confirm sheet. The removal happens at **Execute Action**: the execute service collects every in-review row decided `ignore` (as `R-EXEC-2` states, [#941](https://github.com/jackal998/photo-manager/issues/941)) alongside the delete rows, finalizes the ignore rows to `outcome='ignored'` in one batch (files untouched on disk), and they drop out of the review because the manifest loads only rows `WHERE outcome=''` (the [#584](https://github.com/jackal998/photo-manager/issues/584) unification). Until then the Execute dialog lists them next to the delete rows, and its type filter can isolate them.
- **Conditions / variants:**
  - Matched rows that are locked are refused under `R-LOCK-1`, which opens the dialog's inline lock-confirm (Cancel / Apply to Unlocked Only / Unlock & Apply) — see [Web — Action dialog (Set Action by Field)](web-ui.md#web--action-dialog-set-action-by-field).
  - The same reversible, deferred Skip is on every row's decision control (the **Skip** segment).
  - The toolbar's bulk **Skip** verb and the preview pane's **Skip** button stage the same reversible decision. The remaining Skip entries **finalize on the spot** instead of deferring: the main-tree right-click **Skip now — drop from this review** (file rows: the selection-aware target set; group header: the group's members) and the menu bar's **List → Skip Selected now**, both finalized at once under `R-SKIP-1` ([#694](https://github.com/jackal998/photo-manager/issues/694)); and the Execute dialog's row-menu **Skip — leave on disk, drop from this review**, which finalizes that one row behind a confirm ("Skip this file?" — Cancel / Yes, skip it). The "now" in the two main-window labels is what marks them as immediate.
