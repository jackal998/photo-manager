### Context menu — Lock / Unlock
- **Area:** Context menu

- **Entry point:** The file-row right-click menu of the main result tree ([frontend/src/components/ContextMenu.tsx](../../frontend/src/components/ContextMenu.tsx)) shows **Lock** (`ctx-lock`) or **Unlock** (`ctx-unlock`) according to the right-clicked row's current state. The same flag is reachable from each row's padlock in the Lock column (`row-lock-{group}-{name}`, [frontend/src/components/result/LockToggle.tsx](../../frontend/src/components/result/LockToggle.tsx)), from the Execute dialog's row menu ([frontend/src/components/execute/ExecuteContextMenu.tsx](../../frontend/src/components/execute/ExecuteContextMenu.tsx)), and from the Set Action dialog's **Lock** / **Unlock** actions (wire values `__lock__` / `__unlock__`).
- **Trigger:** Right-click a file row (single, or part of a multi-selection) and pick **Lock** or **Unlock**.
- **Behaviour:** Sets the `is_locked` flag — orthogonal to `user_decision`, which it leaves alone — on every target row (the whole multi-selection when the right-clicked row is in it, otherwise just that row) in one `PATCH /api/lock`, applied optimistically and reverted if the request fails. A locked row shows a closed padlock and an unlocked row an open one (colour per `R-LOCK-3`), its decision control is disabled, and it is frozen against the writes that would change or act on its decision: a decision write (`PATCH /api/decision`, a Set Action bulk apply, the right-click Apply best-copy), **Skip now**, and Execute of a row decided **Delete** are refused under `R-LOCK-1` and `R-LOCK-4`, and the refusal opens the lock-confirm dialog — see [Execute Action — lock-confirm dialog](execute-action.md#execute-action--lock-confirm-dialog). The group header's **Keep best · delete rest** button instead leaves locked rows untouched.
- **Conditions / variants:** Lock and Unlock never open the lock-confirm dialog themselves — `PATCH /api/lock` has no lock gate and the Set Action dialog's lock/unlock actions bypass it — so they stay the escape valve for the freeze. The group-header menu has no Lock/Unlock. In the Execute dialog's row menu they act on the right-clicked row only.
- **Related:** [PR #175](https://github.com/jackal998/photo-manager/pull/175) (closes [#164](https://github.com/jackal998/photo-manager/issues/164)); selection behaviour under [Web — main result tree multi-selection](web-ui.md#web--main-result-tree-multi-selection); QA scenarios [`qa/web/scenarios/s35_lock_via_context_menu.py`](../../qa/web/scenarios/s35_lock_via_context_menu.py) (Lock → Unlock round trip on one row and then two rows, `is_locked` read back via `GET /api/manifest`) and [`qa/web/scenarios/s53_execute_dialog_lock_decision.py`](../../qa/web/scenarios/s53_execute_dialog_lock_decision.py) (the Execute-dialog route, plus a locked row's decision write answering 409); unit [`tests/test_web_review_routes.py`](../../tests/test_web_review_routes.py) (`test_lock_returns_updated_count`, `test_unlock_also_works`, `test_locked_row_without_flags_returns_409`).

### Context menu — Open Folder
- **Area:** Context menu

- **Entry point:** The file-row right-click menu of the main result tree — **Open folder** (`ctx-open-folder`, [frontend/src/components/ContextMenu.tsx](../../frontend/src/components/ContextMenu.tsx)). It is not on the group-header menu or on the Execute dialog's row menu.
- **Trigger:** Right-click a file row and pick **Open folder**.
- **Behaviour:** Targets only the right-clicked row, even inside a multi-selection. `store.revealInExplorer` posts `POST /api/reveal {file_path}`; the server accepts it only from localhost and only for a path under the allowed roots (the scanned folders), then launches `explorer /select,<path>` fire-and-forget, so Explorer opens the containing folder with the file pre-selected. Windows only: on any other platform the endpoint answers 501 `platform_unsupported`. A failed reveal is non-fatal — the manifest is untouched and the error is written to `execute.executeError`, which the footer shows as its `main-execute-error` line ("Action error: …"; a failed Explorer launch reads "The file manager could not be opened.") while the Execute dialog is closed; with that dialog open, the dialog shows the error itself. See [Main window — status bar baseline](main-window.md#main-window--status-bar-baseline) for the footer's error lines.
- **Conditions / variants:** The full-resolution viewer's load-error fallback button (**Open in default app**) calls the same reveal. Double-clicking a row does not reveal it — that opens the in-app viewer (see [Main window — results tree double-click](main-window.md#main-window--results-tree-double-click)).
- **Related:** Originally part of the [PR #19](https://github.com/jackal998/photo-manager/pull/19) context-menu redesign; extracted into a shared helper in [PR #198](https://github.com/jackal998/photo-manager/pull/198). QA scenario [`qa/web/scenarios/s19_context_menu_open_folder.py`](../../qa/web/scenarios/s19_context_menu_open_folder.py) (the item fires a `POST /api/reveal` carrying the right `file_path` — the driver captures the first such request; 200 on Windows, 501 elsewhere); unit [`tests/test_web_execute_routes.py`](../../tests/test_web_execute_routes.py) (`TestPostReveal`: non-localhost 403, non-Windows 501, Windows launches Explorer once), [`frontend/src/components/ContextMenu.test.tsx`](../../frontend/src/components/ContextMenu.test.tsx) (Open folder calls `revealInExplorer`), [`frontend/src/App.test.tsx`](../../frontend/src/App.test.tsx) (the `main-execute-error` footer line and its suppression while the Execute dialog is open).

### Context menu — Set Action (per-file)
- **Area:** Context menu

- **Entry point:** The file-row right-click menu of the main result tree (`context-menu`, [frontend/src/components/ContextMenu.tsx](../../frontend/src/components/ContextMenu.tsx)) — three decision items at its top. The Execute dialog's row menu ([frontend/src/components/execute/ExecuteContextMenu.tsx](../../frontend/src/components/execute/ExecuteContextMenu.tsx)) carries the same three.
- **Trigger:** Right-click a file row (single, or part of a multi-selection) and pick **Keep this file**, **Delete — move to Recycle Bin**, or **Skip now — drop from this review**.
- **Behaviour:** The items act on the target set: the whole multi-selection when the right-clicked row belongs to it, otherwise just that row (which then becomes the selection). **Keep** / **Delete** write `user_decision` `''` / `delete` for every target in one `PATCH /api/decision`, applied optimistically to the rows in place (no manifest reload) and reverted on any failure. If any target is locked, the refusal under `R-LOCK-1` opens the lock-confirm dialog with the deferred-decision wording — **Cancel**, **Unlocked only** (re-sends the decision for the unlocked targets only) or **Unlock & Apply** (the forced re-send of `R-LOCK-2`) — see [Execute Action — lock-confirm dialog](execute-action.md#execute-action--lock-confirm-dialog). **Skip now** does not stage a decision: it finalizes the targets at once under `R-SKIP-1`, via `POST /api/remove` ([#694](https://github.com/jackal998/photo-manager/issues/694)); the staged, reversible Skip lives on the row's own decision control and in the Set Action dialog — see [Bulk regex — remove from list (deferred decision)](bulk-operations.md#bulk-regex--remove-from-list-deferred-decision).
- **Conditions / variants:** The same menu also offers **Set Action by Field…** (opens the Set Action dialog pre-filled from the right-clicked column and seeded from that row, #735 / #893), **Execute Action (only selected)…**, Lock / Unlock, Open folder, and **Apply best-copy decisions to this group** ([#744](https://github.com/jackal998/photo-manager/issues/744)). The group-header menu has no Keep / Delete. In the Execute dialog's row menu the verbs act on the right-clicked row only, and its Skip finalizes that row behind a confirm ("Skip this file?").
- **Related:** Foundation in [PR #19](https://github.com/jackal998/photo-manager/pull/19); [#694](https://github.com/jackal998/photo-manager/issues/694); [#733](https://github.com/jackal998/photo-manager/issues/733) (decision writes lock-gated); [#735](https://github.com/jackal998/photo-manager/issues/735); selection behaviour under [Web — main result tree multi-selection](web-ui.md#web--main-result-tree-multi-selection); QA scenarios [`qa/web/scenarios/s15_context_menu.py`](../../qa/web/scenarios/s15_context_menu.py) (right-click Delete / Keep, By-Field and Execute-selected present, group-row reduced menu), [`qa/web/scenarios/s20_multi_remove_from_list.py`](../../qa/web/scenarios/s20_multi_remove_from_list.py) (multi-selection fan-out + target resolution) and [`qa/web/scenarios/s53_execute_dialog_lock_decision.py`](../../qa/web/scenarios/s53_execute_dialog_lock_decision.py) (Execute-dialog row menu Delete, and a locked row's 409 → lock-confirm → Cancel leaving the row byte-for-byte unchanged); unit [`frontend/src/components/ContextMenu.test.tsx`](../../frontend/src/components/ContextMenu.test.tsx) and [`tests/test_web_review_routes.py`](../../tests/test_web_review_routes.py) (`PATCH /api/decision`: 409 without flags, `force_locked` applies and unlocks, `skip_locked` writes the unlocked rows only).

### Empty area context menu
- **Area:** Context menu

- **Entry point:** None as a feature. The app's own context menu (`context-menu`, [frontend/src/components/ContextMenu.tsx](../../frontend/src/components/ContextMenu.tsx)) opens only from a right-click on a **file row** ([frontend/src/components/result/FileRow.tsx](../../frontend/src/components/result/FileRow.tsx)) or a **group header** ([frontend/src/components/result/GroupRow.tsx](../../frontend/src/components/result/GroupRow.tsx)); the tree's scroll container ([frontend/src/components/ResultTree.tsx](../../frontend/src/components/ResultTree.tsx)), its column header and the menu bar carry no context-menu handler.
- **Trigger:** The user right-clicks a non-row surface — the empty area below the last row, or the empty gap of the menu bar.
- **Behaviour:** No app menu opens. The app mounts the menu only while its menu state is open, and only the file-row handler (the full, selection-aware file-row menu) and the group-header handler (the reduced group menu — Set Action by Field…, Skip now, Apply best-copy; #735 / #744) set that state. Nothing on the empty surface calls `preventDefault`, so the browser's own context menu may appear there instead. If an app menu is already open, the right-click lands outside it and dismisses it.
- **Conditions / variants:** Independent of the selection. A row right-click needs no prior left-click — the row under the pointer drives the menu, and a row outside the current selection becomes the new single selection.
- **Related:** QA scenario [`qa/web/scenarios/s25_empty_area_context_menu.py`](../../qa/web/scenarios/s25_empty_area_context_menu.py) (branches A / B: no `context-menu` after right-clicking below the last row or in the menu-bar gap; C / D: a row right-click with and without a prior left-click does open it); menu contents under [Web — main result tree multi-selection](web-ui.md#web--main-result-tree-multi-selection).
