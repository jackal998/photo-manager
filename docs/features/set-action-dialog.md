Entries for the **Set Action dialog** area of the feature inventory. The index and the section schema are in [`../features.md`](../features.md).

### Set Action dialog — dual-section Simple + Regex view
- **Area:** Set Action dialog

- **Entry point:** The string-field body of the Set Action dialog: [frontend/src/components/action/RegexPanel.tsx](../../frontend/src/components/action/RegexPanel.tsx) (Simple row + Regex row), mounted by [frontend/src/components/action/ActionDialog.tsx](../../frontend/src/components/action/ActionDialog.tsx) whenever the selected field is not numeric. The rest of the dialog (how to open it, the action combo, Recent, the delete-confirm and lock-confirm flows) is described in [Web — Action dialog (Set Action by Field)](web-ui.md#web--action-dialog-set-action-by-field).
- **Trigger:** The dialog is open with a string field selected: File Name (the default), Folder, Resolution, Action or Lock. Both rows are always shown together. There is no mode toggle.
- **Behaviour:**
  - **Simple row** (`action-simple-op` + `action-simple-text`) reads "Find rows where it [contains | starts with | ends with | exactly matches] [text]". Every edit writes through to the Regex input. The text is regex-escaped, then left bare / prefixed `^` / suffixed `$` / wrapped `^…$` for the four operators, so plain text containing `.`, `(` or `+` stays literal.
  - **Regex row** (`action-regex-input`) holds the pattern that is actually sent. It is the single source of truth. A ○ / ✓ / ✗ icon sits beside it (see [Set Action dialog — live preview + validation](#set-action-dialog--live-preview--validation)). Seven cheatsheet chips (`action-cheatsheet-*`: `.*`, `\d`, `\w`, `^`, `$`, `\.`, `[abc]`) insert their token at the caret, replacing any selection, and leave the caret after it.
  - **The sync runs both ways (Regex → Simple since [#899](https://github.com/jackal998/photo-manager/issues/899)).** The Simple row is derived from the pattern when the panel mounts, which happens on open and on every field change (the panel is keyed on the field). It is derived by reverse-parsing the pattern (`reverseParseSimple` in [frontend/src/lib/patternSummary.ts](../../frontend/src/lib/patternSummary.ts)). A pattern that Simple cannot express leaves the row at "contains" + blank on mount. Typing in the Regex row, inserting a chip or picking a Recent entry re-derives the Simple row whenever the new pattern is Simple-representable; a pattern it cannot represent leaves the row as it was.
  - Matching runs on the server (`POST /api/action/bulk-decide`, [core/app_service/action_resolve.py](../../core/app_service/action_resolve.py)) with Python `re`, **case-insensitive**. Each field is matched against: File Name = the basename; Folder = the row's folder path; Action = the stored decision (`""` for Keep / no decision, `delete`, `ignore`); Lock = `Locked` or `""`; Resolution = `W×H`. See [Set Action dialog — Score / Lock / Resolution fields](#set-action-dialog--score--lock--resolution-fields).
- **Conditions / variants:**
  - **Empty values:** a blank Simple text always produces an empty pattern, whichever operator is selected, so "exactly matches" + blank does **not** produce `^$`. To select rows whose value is empty, type `^$` into the Regex row (for example Lock `^$` = unlocked rows, Action `^$` = rows with no decision). An empty pattern matches nothing (the server returns no rows for it), so Apply with an empty pattern is a no-op.
  - **No groups in the review:** when the loaded review has zero groups, the Simple operator and text are disabled and an italic note reads "Write-through preview unavailable — Simple inputs are read-only on this entry point." The Regex row stays usable ([#689](https://github.com/jackal998/photo-manager/issues/689), s55).
  - **Starting state:** every open resets the dialog to field "File Name" (unless the entry point pre-fills a field from the clicked column, [#735](https://github.com/jackal998/photo-manager/issues/735)), Simple operator "contains" and action **Delete**. None of the three is remembered between opens. Opening from a row seeds the pattern with that row's escaped value ([#893](https://github.com/jackal998/photo-manager/issues/893)), and the Simple row then shows it as `contains <value>`. Which entry point seeds from which row is listed under [Web — Action dialog (Set Action by Field)](web-ui.md#web--action-dialog-set-action-by-field).
  - Picking a numeric field replaces both rows with the numeric panel ([Set Action dialog — numeric comparison panel](#set-action-dialog--numeric-comparison-panel)).
  - **Keyboard and dismissal:** there is no Apply shortcut, and there are no Alt mnemonics or inline clear buttons (the retired desktop dialog's Ctrl+Enter, Alt-letter mnemonics and × buttons were not ported). Escape closes the dialog unless an apply is in flight. An outside interaction does not close it, as `R-DIALOG-1` states ([#764](https://github.com/jackal998/photo-manager/issues/764)). The dialog is always a modal overlay.
  - A successful Apply closes the dialog and the result tree re-renders from the server's post-apply groups. The retired desktop dialog stayed open and showed "Applied to N rows" instead.
- **Related:** [frontend/src/components/action/RegexPanel.tsx](../../frontend/src/components/action/RegexPanel.tsx); `frontend/src/lib/regexEscape.ts`; `frontend/src/lib/patternSummary.ts` (`reverseParseSimple`); `core/app_service/action_resolve.py` (`resolve_matched_paths`, `_get_record_field`); component tests [`frontend/src/components/action/ActionDialog.test.tsx`](../../frontend/src/components/action/ActionDialog.test.tsx) (write-through for all four operators, the zero-groups branch, #893 seeding); unit tests `tests/test_action_resolve.py`; QA scenarios [`qa/web/scenarios/s31_simple_mode_regex.py`](../../qa/web/scenarios/s31_simple_mode_regex.py) (Simple write-through → preview → Apply), [`qa/web/scenarios/s55_action_dialog_no_match_fn.py`](../../qa/web/scenarios/s55_action_dialog_no_match_fn.py) (zero-groups branch), [`qa/web/scenarios/s73_action_seed_and_page_scroll.py`](../../qa/web/scenarios/s73_action_seed_and_page_scroll.py) (#893 row seed). ### Set Action dialog — live preview + validation
- **Area:** Set Action dialog

- **Entry point:** The match counter, error line and Preview list in [frontend/src/components/action/ActionDialog.tsx](../../frontend/src/components/action/ActionDialog.tsx); the regex check in [frontend/src/components/action/RegexPanel.tsx](../../frontend/src/components/action/RegexPanel.tsx); the dry run of `POST /api/action/bulk-decide` with `preview: true` ([app/web/routes/action.py](../../app/web/routes/action.py) → `bulk_decide` in [core/app_service/action_service.py](../../core/app_service/action_service.py)).
- **Trigger:** Any change of field or pattern: the Simple row, the Regex row, a cheatsheet chip, a Recent pick, or a numeric-panel input. The request fires 300 ms after the last change. Nothing is requested while the pattern is empty. Changing only the action combo does not re-run it.
- **Behaviour:**
  - The server resolves the pattern against the manifest exactly as a real Apply would, writes nothing, and returns the match count and paths. The store drops out-of-order responses, so the counter never shows a superseded pattern's result.
  - **Match counter** (`action-match-counter`) shows "N of M matched", where M is the number of files in the loaded review. For a Top-N pattern it shows "N matched (≤n per group × G groups)". It shows "—" while the pattern is empty or the answer has not arrived or failed, and "updating…" appears beside it while a request is in flight.
  - **Preview list** (`action-preview-list`) shows the full path of every matched row, in group order, in a scrollable box. "No matches" appears when the count is 0. The server does not cap the list today, so the "…and N more" footer (`action-preview-truncated`) never appears in practice.
  - The preview **counts locked rows too**. The locked-rows gate runs only on a real Apply (the lock-confirm flow is described under [Web — Action dialog (Set Action by Field)](web-ui.md#web--action-dialog-set-action-by-field)).
  - **Validation:** the ○ / ✓ / ✗ icon updates on every keystroke. For an invalid pattern, a red "Invalid regex: <message>" line (`action-validation-error`) appears under the Regex row. That check uses the browser's JavaScript `RegExp`, while matching uses the server's Python `re`. When the server rejects a pattern (HTTP 400 `invalid_pattern`), its response shows in the dialog's red alert line instead of a preview. The two grammars differ at the edges (e.g. `(?P<name>…)` is Python-only), so the server's answer is the authoritative one. The numeric panel has its own input check ([Set Action dialog — numeric comparison panel](#set-action-dialog--numeric-comparison-panel)).
  - **Apply is never disabled by the pattern.** It is disabled only while a request is running or when no manifest is loaded ([#397](https://github.com/jackal998/photo-manager/issues/397), restored on the web by [#741](https://github.com/jackal998/photo-manager/issues/741)). An empty pattern applies to nothing.
- **Conditions / variants:** The same dialog, with the same preview, opens from the toolbar, the menu bar, a result-tree row's right-click, and the Execute Action dialog's row menu ([#316](https://github.com/jackal998/photo-manager/issues/316)). The Execute route opens it manifest-wide, with no row seed. A successful Apply closes the dialog and the tree re-renders from the server's post-apply groups; the web shows no separate status-bar notice for it.
- **Related:** `app/web/routes/action.py` (400 `invalid_pattern`, 409 `locked_paths`, 422); `core/app_service/action_service.py` (`bulk_decide`, `preview`); `core/app_service/action_resolve.py`; `frontend/src/store/useAppStore.ts` (`previewBulkDecide`, stale-response sequence); unit tests `tests/test_web_action_routes.py`, `tests/test_action_resolve.py`, [`frontend/src/components/action/ActionDialog.test.tsx`](../../frontend/src/components/action/ActionDialog.test.tsx) (match counter, Apply enabled on an empty pattern), `frontend/src/store/useAppStore.test.ts` (out-of-order preview dropped); QA scenarios [`qa/web/scenarios/s14_action_by_regex.py`](../../qa/web/scenarios/s14_action_by_regex.py) (menu-bar route, live counter, Apply), [`qa/web/scenarios/s30_execute_dialog_regex_right_click.py`](../../qa/web/scenarios/s30_execute_dialog_regex_right_click.py) (Execute-dialog row menu → same dialog). History: [PR #162](https://github.com/jackal998/photo-manager/pull/162) (live preview, validation, right-click parity); [#395](https://github.com/jackal998/photo-manager/issues/395) removed the desktop "Test against:" playground.

### Set Action dialog — numeric comparison panel
- **Area:** Set Action dialog

- **Entry point:** [frontend/src/components/action/NumericPanel.tsx](../../frontend/src/components/action/NumericPanel.tsx) (`action-numeric-row`). It replaces the Simple + Regex rows when the field is numeric. The server resolves it with `resolve_matched_paths` → `select_paths_by_threshold` / `select_paths_top_n` in [core/app_service/action_resolve.py](../../core/app_service/action_resolve.py).
- **Trigger:** Picking one of the six numeric fields: Size (Bytes), Group Count, Similarity, Score, Creation Date or Shot Date. One dialog component serves every entry point (toolbar, menu bar, row right-click, Execute dialog row menu), so every route reaches the panel.
- **Behaviour:**
  - The panel has two radio modes:
    - **Threshold** is the default: "Where the value is [> | >= | < | <= | == | !=] [value]". The operator defaults to `>=`, and the input encodes as `__cmp__:OP:VALUE`.
    - **Top N per group:** "Pick the [Top | Bottom] [N] in each group". It defaults to Top, 3, and encodes as `__top_n__:N:desc` (Top) or `__top_n__:N:asc` (Bottom). Switching to Top N sends that default pattern immediately, so a preview appears without typing.
  - The pseudo-pattern takes the same `POST /api/action/bulk-decide` path, for preview and for Apply, as a regex does. A `__cmp__:` / `__top_n__:` prefix commits the server to that branch: a malformed payload is rejected (HTTP 422) and is never re-read as a regex.
  - **Threshold:** rows with no value for the field are skipped, and dates are compared as timestamps.
  - **Top N:** within each group, rows are ranked by the field, with ties broken by file path, so the same configuration always selects the same rows. Rows with no value are left out of the ranking. A group with fewer than N rankable rows contributes all of them.
  - The ranking is `core.services.auto_select.top_n_paths` ([#778](https://github.com/jackal998/photo-manager/issues/778)), the same rule behind the per-group "Apply best-copy decisions to this group" row-menu item and the "Keep best · delete rest" group-row button ([#744](https://github.com/jackal998/photo-manager/issues/744); see [Web — Context menu: Apply best-copy decisions to this group](web-ui.md#web--context-menu-apply-best-copy-decisions-to-this-group)). A Top-N Apply sets the chosen action on the selected rows only, while those two also decide the rest of the group.
  - **What each field compares:**
    - **Size (Bytes):** bytes. The result tree shows a human-readable size.
    - **Group Count:** the number of files in the row's group.
    - **Similarity:** the row's stored pHash Hamming distance (0 = identical, larger = less similar). This is not the percentage the Similarity badge shows.
    - **Score:** the 0–1 value the Score column shows.
    - **Creation Date / Shot Date:** the stored date-time, compared as a timestamp. A typed `YYYY-MM-DD` means local midnight of that day, so `==` matches only rows stamped exactly 00:00:00; bracket a day with `>=` and `<` instead.
- **Conditions / variants:**
  - **Threshold input:** the placeholder reads "type a date (YYYY-MM-DD)…" for the two date fields and "type a number…" otherwise. Input that fails the check (a date not shaped `YYYY-MM-DD`, or a non-number) shows "Couldn't parse '<input>' as a value for this field" (`action-numeric-error`) and clears the pattern. The counter then shows "—" and nothing is previewed. The date check tests the shape only: `2026-13-45` passes it and matches nothing. There is no ✓ / ✗ icon in this mode.
  - **Top N:** the counter reads "N matched (≤n per group × G groups)". The N field is a number input bounded 1–10,000 (the stepper stops there; a typed value is checked only to be ≥ 1). Preview rows are plain file paths, as for a regex.
  - **Switching fields keeps the encoded pattern.** The panel remounts on a field change and renders blank inputs, but the store keeps the last pattern unless it was the previous field's row seed or empty, and numeric fields have no seed. A `__cmp__:` / `__top_n__:` pattern built for one field therefore survives a switch to another numeric field, and preview and Apply run it against the new field — e.g. a Score `>= 0.5` becomes Shot Date `>= 0.5`, read as a timestamp. Re-enter the condition after changing the field.
  - Numeric patterns are never recorded in Recent.
- **Related:** [PR #221](https://github.com/jackal998/photo-manager/pull/221) (closes [#209](https://github.com/jackal998/photo-manager/issues/209)); `core/app_service/action_resolve.py`; `core/services/auto_select.py` (`top_n_paths`); unit tests `tests/test_action_resolve.py`, `tests/test_topn_keeper_parity.py`, [`frontend/src/components/action/ActionDialog.test.tsx`](../../frontend/src/components/action/ActionDialog.test.tsx) (`__cmp__` / `__top_n__` encoding). QA scenarios [`qa/web/scenarios/s43_numeric_condition.py`](../../qa/web/scenarios/s43_numeric_condition.py) (Size threshold → Apply → exact 3-of-5 split), [`qa/web/scenarios/s50_select_numeric_panel_from_main_window.py`](../../qa/web/scenarios/s50_select_numeric_panel_from_main_window.py) (menu-bar route reaches the panel), [`qa/web/scenarios/s56_action_dialog_apply_by_score.py`](../../qa/web/scenarios/s56_action_dialog_apply_by_score.py) (Score threshold writes rows — the [#392](https://github.com/jackal998/photo-manager/issues/392) regression).

### Set Action dialog — Score / Lock / Resolution fields
- **Area:** Set Action dialog

- **Entry point:** The Field combo (`action-field-combo`) in [frontend/src/components/action/ActionDialog.tsx](../../frontend/src/components/action/ActionDialog.tsx). The field → record-attribute mapping lives in [core/app_service/action_resolve.py](../../core/app_service/action_resolve.py) (`_FIELD_TO_ATTR`, `_get_record_field`, `_numeric_value_for`).
- **Trigger:** User opens the dialog from any entry point and expands the Field combo.
- **Behaviour:** Every entry point shows the same field list, in this order, because one mounted `ActionDialog` serves them all: File Name, Folder, Size (Bytes), Group Count, Similarity, Score, Creation Date, Shot Date, Resolution, Action, Lock. The six numeric fields open the numeric panel ([Set Action dialog — numeric comparison panel](#set-action-dialog--numeric-comparison-panel)). The other five take a regex ([Set Action dialog — dual-section Simple + Regex view](#set-action-dialog--dual-section-simple--regex-view)).
  - **Score** is numeric: the 0–1 value the Score column shows.
  - **Lock** matches the string `Locked` for a locked row and `""` for an unlocked one: use `^Locked$` / `^$`.
  - **Resolution** matches `W×H`, with the `×` sign and no spaces (e.g. `^1920×1080$`), which is the same text the app displays for dimensions. Rows without both dimensions (typically videos) never match.
  - **Action** matches the stored decision: `""` (Keep / no decision), `delete`, or `ignore` (Skip).
- **Conditions / variants:** Labels are translated through the `web.column.*` keys. The option value stays the canonical English label, which is what the server receives. The Execute Action dialog's row menu opens this same component, so its field list is identical by construction. The retired desktop client once had a shorter hard-coded list on that route ([#392](https://github.com/jackal998/photo-manager/issues/392)). The same 11 labels are duplicated in `frontend/src/lib/actionDialogFields.ts` (`ACTION_DIALOG_FIELD_OPTIONS`, which validates a pre-filled field) and are kept in step with the combo's list by hand.
- **Related:** [PR #250](https://github.com/jackal998/photo-manager/pull/250) (closes [#238](https://github.com/jackal998/photo-manager/issues/238)); `core/app_service/action_resolve.py`; `frontend/src/lib/actionDialogFields.ts`; `frontend/src/lib/format.ts` (`formatDims`); unit tests `tests/test_action_resolve.py`, [`frontend/src/lib/actionDialogFields.test.ts`](../../frontend/src/lib/actionDialogFields.test.ts); QA scenarios [`qa/web/scenarios/s50_select_numeric_panel_from_main_window.py`](../../qa/web/scenarios/s50_select_numeric_panel_from_main_window.py) (Score opens the numeric panel), [`qa/web/scenarios/s56_action_dialog_apply_by_score.py`](../../qa/web/scenarios/s56_action_dialog_apply_by_score.py) (Score threshold Apply).

### Set Action dialog — geometry persistence
- **Area:** Set Action dialog

- **Entry point:** The shared overlay-geometry mechanism: `useOverlayGeometry("action", …)` in [frontend/src/components/action/ActionDialog.tsx](../../frontend/src/components/action/ActionDialog.tsx), the persistence helpers in [frontend/src/lib/overlayGeometry.ts](../../frontend/src/lib/overlayGeometry.ts), the title bar `action-title-bar` and the corner grip `action-resize-handle`. The full behaviour is described in [Web — overlay window geometry (movable / resizable / persisted)](web-ui.md#web--overlay-window-geometry-movable--resizable--persisted).
- **Trigger:** User drags the dialog's title bar (move) or its bottom-right grip (resize).
- **Behaviour:** The position, plus the size after a resize, is saved to the browser's localStorage under `pm.overlay-geometry.action.v1`, once per gesture. It is restored the next time the dialog opens, including after a page reload. A move stores position only, so the dialog still grows when its Preview list appears. A resize pins width and height; the body (`action-body`) then scrolls while the Cancel / Apply footer stays in view. Saved geometry is clamped into the current viewport, with a 320×280 px minimum.
- **Conditions / variants:** On first open (nothing saved, or storage unreadable) the dialog uses its default centered `max-w-2xl` layout. The geometry is stored per browser profile, not in `settings.json`. The web has **no Reset window size button or shortcut**; the retired desktop dialog's Reset button and Ctrl+0 have no counterpart. Clearing the `pm.overlay-geometry.action.v1` key (browser site data) returns the dialog to its default. The dialog is a single column with the preview under the inputs, so there is no splitter position to persist.
- **Related:** issue [#739](https://github.com/jackal998/photo-manager/issues/739) (divergence D7 in [`docs/audits/web-divergence-list-2026-07.md`](../audits/web-divergence-list-2026-07.md)); QA scenario [`qa/web/scenarios/s48_dialog_geometry_persist.py`](../../qa/web/scenarios/s48_dialog_geometry_persist.py) (move keeps auto-height, resize to the floor scrolls the body, geometry restored after reload); unit tests [`frontend/src/lib/overlayGeometry.test.ts`](../../frontend/src/lib/overlayGeometry.test.ts), [`frontend/src/hooks/useOverlayGeometry.test.tsx`](../../frontend/src/hooks/useOverlayGeometry.test.tsx). Desktop history: [PR #228](https://github.com/jackal998/photo-manager/pull/228) (closes [#215](https://github.com/jackal998/photo-manager/issues/215)), [#391](https://github.com/jackal998/photo-manager/issues/391).
